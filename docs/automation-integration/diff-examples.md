## 数据结构分析

### 关键字段说明：
- `old_path` / `new_path`: 文件的旧路径和新路径
- `new_file`: 是否为新建文件
- `deleted_file`: 是否为删除文件  
- `renamed_file`: 是否为重命名文件
- `diff`: 具体的diff内容，包含行号变更信息

### 文件变更类型识别：
1. **新增文件**: `new_file: true`
2. **删除文件**: `deleted_file: true` 
3. **重命名文件**: `renamed_file: true`
4. **修改文件**: 以上都为false，只是内容修改

### 测试文件识别规则：
- 路径包含 `/test/` 或 `/src/test/`
- 文件名以 `Test.java` 结尾
- 类名包含 `Test`

### diff内容问题：
- diff可能省略大量内容（用省略号表示）
- @TestId注解和方法名可能被省略
- 需要调用文件内容API获取完整源码

## 处理逻辑设计

### 多文件处理流程：
1. **遍历所有变更文件**
2. **筛选测试文件**：根据路径和文件名规则过滤
3. **分类处理**：
   - 删除文件：标记相关用例为无效
   - 新增/修改/重命名：获取完整文件内容进行解析
4. **获取完整源码**：对需要处理的测试文件调用文件内容API
5. **解析@TestId**：从完整源码中提取注解和方法信息
6. **同步用例**：根据解析结果更新测试管理平台

### 核心处理逻辑：
```typescript
// 1. 筛选测试文件
const testFiles = diffData.filter(file => isTestFile(file.new_path || file.old_path));

// 2. 分类处理
for (const file of testFiles) {
  if (file.deleted_file) {
    // 处理删除文件：标记相关用例
    await handleDeletedTestFile(file.old_path);
  } else {
    // 获取完整文件内容
    const fullContent = await getFileContent(projectId, file.new_path, branch);
    // 解析@TestId和测试方法
    const testMethods = parseTestMethods(fullContent);
    // 同步到测试管理平台
    await syncTestCases(testMethods, file.new_path);
  }
}
```
