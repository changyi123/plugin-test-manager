# 自动化测试用例同步 - 最终方案汇总

## 一、方案概览

### 1.1 核心目标
- 监听代码仓库webhook事件，自动同步测试用例到测试管理平台
- 支持用例的创建、更新操作
- 提供管理界面查看同步记录和手动触发功能

### 1.2 技术架构
```
代码仓库 → Webhook → 队列存储 → 异步处理 → 用例同步 → 测试管理
                         ↓
                    同步管理页面
```

## 二、数据存储设计

### 2.1 自定义字段（存储在测试用例上）
| 字段Key | 字段名称 | 类型 | 说明 |
|---------|---------|------|------|
| automationCaseId | 自动化用例唯一标识 | text | @TestId注解值，用于唯一定位 |
| automationFilePath | 自动化代码路径 | text | 代码文件完整路径 |
| automationRepository | 自动化代码仓库 | text | 仓库名称 |
| automationClassName | 自动化测试类名 | text | Java类名 |
| automationMethodName | 自动化测试方法名 | text | 测试方法名 |
| automationLastCommit | 最后同步CommitId | text | 追踪版本 |
| automationLastSyncTime | 最后同步时间 | datetime | 同步时间戳 |
| automationFramework | 自动化测试框架 | text | JUnit/TestNG |

### 2.2 数据库表

#### AutomationWebhookQueue（Webhook队列表）
- webhookUuid: webhook事件ID
- repositoryId: 仓库ID
- repositoryName: 仓库名称
- branchName: 分支名称
- commitIds: commit数组
- payload: 完整webhook数据
- status: pending/processing/completed/failed
- retryCount: 重试次数
- processedTime: 处理时间

#### AutomationSyncLog（同步记录表）
- webhookQueueId: 关联队列ID
- repositoryId/Name: 仓库信息
- commitId: 提交ID
- branchName: 分支
- syncStatus: success/failed/partial
- 统计数据: processedFiles/createdCases/updatedCases/skippedCases/failedCases
- errorDetails: 错误详情
- syncStartTime/EndTime: 执行时间

## 三、核心流程

### 3.1 Webhook接收流程
```javascript
POST /webtriggers/codeCommitWebhook

1. 接收webhook事件
2. 验证分支（环境变量SYNC_BRANCH，默认master）
3. 存储到队列表（status=pending）
4. 立即返回200
```

### 3.2 队列处理流程（定时任务，30秒一次）
```javascript
1. 查询pending状态记录（每次最多5条）
2. 更新为processing状态
3. 依次处理每个webhook事件：
   - 获取配置文件(automation-test-map.json)
   - 如果不存在，跳过处理
   - 获取每个commit的diff
   - 过滤配置中声明的文件
   - 获取文件完整内容
   - 解析测试用例
   - 同步到测试管理
4. 更新状态为completed/failed
5. 记录同步日志
```

### 3.3 用例解析逻辑
```java
// 查找的注解格式
@TestId("TC_001")
public void testMethodName() {
    // 测试代码
}
```

提取信息：
- TestId值 → automationCaseId
- 方法名 → 用例名称和automationMethodName
- 类名 → automationClassName
- 文件路径 → automationFilePath

### 3.4 用例同步逻辑
```javascript
// 1. 通过IQL查询已存在的用例
const iql = '\'自动化用例唯一标识\' = "TC_001"';

// 2. 查询配置文件中的目录映射
const moduleId = await getModuleIdByPath(modulePath);

// 3. 如果目录不存在，跳过该用例

// 4. 创建或更新用例
if (existingCase) {
    updateTestCase(caseId, data);
} else {
    createTestCase(data);
}
```

## 四、配置文件规范

### 4.1 automation-test-map.json（代码仓库根目录）
```json
{
  "testingFramework": "JUnit",
  "mappings": {
    "src/test/java/com/cfca/test/Code6601Test.java": "全部用例库/用户认证",
    "src/test/java/com/cfca/test/Code6602Test.java": "全部用例库/工作台"
  }
}
```

- 文件不存在时，跳过整个仓库的同步
- mappings中的key是文件路径，value是测试管理中的目录路径
- 只处理mappings中声明的文件

## 五、管理页面功能

### 5.1 页面位置
测试管理配置 → 自动化同步管理

### 5.2 功能模块
1. **同步记录列表**
   - 显示所有同步历史
   - 支持按仓库、状态筛选
   - 显示统计信息（成功/失败数量）
   - 失败记录支持手动重试

2. **手动同步**
   - 输入仓库名称
   - 输入文件路径列表
   - 触发全量同步
   - 用于初始化场景

3. **配置管理**
   - 查看当前配置
   - 测试连接

## 六、接口清单

### 6.1 内部接口（测试管理提供）

| 接口 | 路径 | 说明 |
|------|------|------|
| Webhook接收 | POST /webtriggers/codeCommitWebhook | 接收代码提交事件 |
| 手动同步 | POST /webtriggers/automationManualSync | 手动触发同步 |
| 重试失败 | POST /webtriggers/automationSyncRetry | 重试失败记录 |

### 6.2 外部接口（调用代码平台）

| 接口 | 说明 | 鉴权 |
|------|------|------|
| GET /projects/{id}/repository/files/{path}/raw | 获取文件内容 | Private-Token |
| GET /projects/{id}/repository/commits/{sha}/diff | 获取commit diff | Private-Token |

## 七、环境变量配置

```bash
# 代码平台
CODE_PLATFORM_BASE_URL=https://dce1-dev.gitee.work/api/v8
CODE_PLATFORM_TOKEN=${CODE_PLATFORM_TOKEN}  # 环境变量
CODE_PLATFORM_ENTERPRISE=DCE3

# 同步配置
SYNC_BRANCH=${SYNC_BRANCH:-master}  # 默认master
SYNC_QUEUE_SIZE=5                   # 队列批次
SYNC_RETRY_MAX=3                    # 最大重试
SYNC_TIMEOUT=120000                 # 超时2分钟
```

## 八、关键决策点

| 决策项 | 方案 | 原因 |
|--------|------|------|
| 分支策略 | 只处理master（可配置） | 简化逻辑，通过环境变量控制 |
| 配置文件缺失 | 跳过处理 | 避免误同步 |
| 目录不存在 | 跳过用例 | 不自动创建目录 |
| 用例删除 | 不处理 | 保留历史用例 |
| 重复用例 | 以最新为准 | 基于automationCaseId去重 |
| 队列实现 | 数据库表 | 无需额外中间件 |
| 查询方式 | IQL查询自定义字段 | '自动化用例唯一标识' = "TC_001" |

## 十、注意事项

1. **性能优化**
   - 文件逐个获取，避免内存溢出
   - 队列批次处理，每次最多5条
   - 超时时间2分钟

2. **错误处理**
   - 部分失败不影响整体
   - 详细记录错误信息
   - 支持手动重试

3. **安全考虑**
   - Token存储在环境变量
   - 无需webhook鉴权（内部svc调用）

4. **扩展性**
   - 分支可配置
   - 批次大小可调整
   - 支持更多测试框架（目前只支持Java）
