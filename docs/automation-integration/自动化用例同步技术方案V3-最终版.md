# 自动化测试用例同步技术方案 V3.0 - 最终版

## 一、方案概述

基于Webhook监听代码仓库提交事件，自动解析测试代码变更，实现测试用例的自动创建、更新和管理。系统采用队列化处理机制，确保稳定性和可扩展性。

## 二、系统架构

### 2.1 核心架构
```
代码仓库 → Webhook → 队列存储 → 异步消费 → 用例同步
                         ↓
                    同步记录管理页面
```

### 2.2 模块设计

#### 核心模块
1. **Webhook接收模块** - 快速接收并存储webhook事件
2. **队列消费模块** - 异步处理webhook事件
3. **代码解析模块** - 解析测试代码，提取用例信息
4. **用例同步模块** - 创建/更新测试用例
5. **同步管理模块** - 管理页面，查看记录和手动重试

## 四、详细流程设计

### 4.1 Webhook接收流程

#### 接口定义
```
POST /webtriggers/codeCommitWebhook
```

#### 处理逻辑
```javascript
async function handleWebhook(payload) {
  // 1. 快速验证和过滤
  const branch = extractBranchName(payload.ref);
  const targetBranch = process.env.SYNC_BRANCH || 'master';
  
  if (branch !== targetBranch) {
    return { success: true, message: '非目标分支，跳过处理' };
  }
  
  // 2. 存储到队列表
  const queueId = generateId();
  await saveToQueue({
    id: queueId,
    webhook_uuid: payload.uuid,
    repository_id: payload.repository.id,
    repository_name: payload.repository.name,
    branch_name: branch,
    commit_ids: payload.commits.map(c => c.id),
    payload: JSON.stringify(payload),
    status: 'pending'
  });
  
  // 3. 立即返回成功
  return { success: true, queueId: queueId };
}
```

### 4.2 队列消费流程

#### 消费策略
- 定时任务每30秒执行一次
- 每次处理最多5个pending状态的记录
- 处理失败的记录最多重试3次

```javascript
async function processQueue() {
  // 1. 获取待处理记录
  const pendingRecords = await getPendingRecords(5);
  
  for (const record of pendingRecords) {
    try {
      // 2. 更新状态为processing
      await updateQueueStatus(record.id, 'processing');
      
      // 3. 处理webhook事件
      await processWebhookEvent(record);
      
      // 4. 更新状态为completed
      await updateQueueStatus(record.id, 'completed');
    } catch (error) {
      // 5. 处理失败，更新重试次数
      await handleProcessError(record, error);
    }
  }
}
```

### 4.3 代码解析流程

#### Step 1: 获取配置文件
```javascript
async function getAutomationConfig(repositoryId, branch) {
  try {
    const configPath = encodeURIComponent('automation-test-map.json');
    const url = `${CODE_PLATFORM_BASE_URL}/projects/${repositoryId}/repository/files/${configPath}/raw?ref=${branch}`;
    
    const response = await httpClient.get(url, {
      headers: {
        'Private-Token': process.env.CODE_PLATFORM_TOKEN,
        'enterprise': process.env.CODE_PLATFORM_ENTERPRISE
      }
    });
    
    return JSON.parse(response.data);
  } catch (error) {
    // 配置文件不存在，跳过处理
    console.log('automation-test-map.json not found, skipping sync');
    return null;
  }
}
```

#### Step 2: 获取Diff并过滤文件
```javascript
async function getFilteredDiffs(repositoryId, commitId, config) {
  const diffs = await getCommitDiff(repositoryId, commitId);
  
  if (!config || !config.mappings) {
    return [];
  }
  
  // 只处理配置中声明的文件
  return diffs.filter(diff => 
    config.mappings.hasOwnProperty(diff.new_path)
  );
}
```

#### Step 3: 解析测试用例
```javascript
async function parseTestCases(repositoryId, diff, config, branch) {
  // 1. 获取文件完整内容
  const fileContent = await getFileContent(repositoryId, diff.new_path, branch);
  
  // 2. 解析所有测试方法
  const testMethods = parseTestMethods(fileContent);
  
  // 3. 根据diff确定受影响的方法
  const affectedMethods = findAffectedMethods(testMethods, diff);
  
  // 4. 构建用例信息
  return affectedMethods.map(method => ({
    operation: determineOperation(diff, method),
    automationCaseId: method.testId,
    name: method.methodName,
    testClassName: extractClassName(fileContent),
    testMethodName: method.methodName,
    filePath: diff.new_path,
    modulePath: config.mappings[diff.new_path],
    testingFramework: config.testingFramework,
    repositoryName: repositoryName,
    branchName: branch
  }));
}
```

### 4.4 用例同步流程

```javascript
async function syncTestCases(testCases) {
  const results = {
    created: 0,
    updated: 0,
    failed: 0,
    errors: []
  };
  
  for (const testCase of testCases) {
    try {
      // 1. 查询目录ID
      const moduleId = await getModuleId(testCase.modulePath);
      
      if (!moduleId) {
        // 目录不存在，跳过该用例
        console.log(`Module not found: ${testCase.modulePath}, skipping case`);
        continue;
      }
      
      // 2. 查询是否已存在
      const existingCase = await findCaseByAutomationId(testCase.automationCaseId);
      
      if (existingCase) {
        // 3. 更新用例
        await updateTestCase(existingCase.id, {
          name: testCase.name,
          moduleId: moduleId,
          customFields: {
            automationCaseId: testCase.automationCaseId
          }
        });
        results.updated++;
      } else {
        // 4. 创建用例
        await createTestCase({
          name: testCase.name,
          moduleId: moduleId,
          customFields: {
            automationCaseId: testCase.automationCaseId
          }
        });
        results.created++;
      }
      
      // 5. 更新映射表
      await updateCaseMapping(testCase);
      
    } catch (error) {
      results.failed++;
      results.errors.push({
        testCase: testCase.name,
        error: error.message
      });
    }
  }
  
  return results;
}
```

### 5.2 手动同步功能

```javascript
async function manualSync(params) {
  const { repositoryName, filePaths, branch = 'master' } = params;
  
  // 1. 获取仓库信息
  const repository = await getRepositoryByName(repositoryName);
  
  // 2. 获取配置文件
  const config = await getAutomationConfig(repository.id, branch);
  
  if (!config) {
    throw new Error('配置文件不存在，无法同步');
  }
  
  // 3. 批量处理文件
  const results = [];
  for (const filePath of filePaths) {
    const fileContent = await getFileContent(repository.id, filePath, branch);
    const testCases = parseAllTestCases(fileContent, filePath, config);
    const syncResult = await syncTestCases(testCases);
    results.push(syncResult);
  }
  
  return results;
}
```

## 七、异常处理策略

### 7.1 错误分类处理

| 错误类型 | 处理策略 | 记录方式 |
|---------|---------|---------|
| 配置文件不存在 | 跳过处理 | 记录到sync_log |
| 目录不存在 | 跳过该用例 | 记录到error_details |
| 解析失败 | 跳过该文件 | 详细错误信息记录 |
| API调用失败 | 重试3次 | 记录重试次数 |
| 超时错误 | 标记失败，支持手动重试 | 记录超时信息 |

### 7.2 降级策略
- Webhook处理失败不影响代码提交
- 单个文件处理失败不影响其他文件
- 支持手动补偿机制

## 十一、注意事项

1. **分支处理**: 通过环境变量`SYNC_BRANCH`控制，默认只处理master
2. **配置文件**: 不存在时跳过处理，不会同步任何用例
3. **目录映射**: 目录不存在时跳过该用例，不自动创建
4. **队列处理**: 基于数据库实现，无需额外中间件
5. **用例去重**: 基于`automationCaseId`，以最新提交为准
6. **性能优化**: 文件逐个处理，避免内存问题
7. **错误处理**: 部分失败不影响整体，支持手动重试
