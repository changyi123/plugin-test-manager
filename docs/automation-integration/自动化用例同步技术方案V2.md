# 自动化测试用例同步技术方案 V2.0

## 一、方案概述

监听代码仓库webhook事件，自动解析提交的自动化测试代码变更，实现测试用例的自动创建、更新和删除。

## 二、技术流程设计

### 2.1 完整处理流程

```
Webhook接收 → 获取配置文件 → 过滤文件变更 → 获取Diff内容 → 获取文件全文 → 解析测试用例 → 同步用例
```

### 2.2 详细步骤说明

#### Step 1: Webhook事件接收
- **接收路径**: `/webtriggers/codeCommitWebhook`
- **事件类型**: `push_code`
- **关键字段提取**:
  - `repository.id`: 仓库ID (如: 1652)
  - `repository.name`: 仓库名称 (如: atmTestCode)
  - `ref`: 分支引用 (如: refs/heads/master)
  - `commits[].id`: 提交ID数组
  - `commits[].added/modified/removed`: 文件变更列表

#### Step 2: 获取配置文件
```javascript
// 调用文件内容接口获取配置
GET /projects/{repositoryId}/repository/files/automation-test-map.json/raw?ref={branch}
```

**配置文件结构**:
```json
{
  "testingFramework": "JUnit",
  "mappings": {
    "src/test/java/com/cfca/test/ESS_V4/testcase/Code6601Test.java": "全部用例库/用户认证",
    "src/test/java/com/cfca/test/ESS_V4/testcase/Code6602Test.java": "全部用例库/工作台"
  }
}
```

#### Step 3: 过滤有效文件变更
- 遍历commits中的added/modified/removed文件
- 与配置文件中的mappings进行匹配
- 只处理配置中声明的自动化测试文件

#### Step 4: 获取文件Diff详情
```bash
GET /projects/{repositoryId}/repository/commits/{commitId}/diff
```

**Diff响应结构**:
```json
[
  {
    "old_path": "src/test/java/Code6601Test.java",
    "new_path": "src/test/java/Code6601Test.java", 
    "new_file": false,
    "deleted_file": false,
    "renamed_file": false,
    "diff": "@@ -330,7 +330,9 @@ ..."
  }
]
```

#### Step 5: 获取文件完整内容
```bash
GET /projects/{repositoryId}/repository/files/{encodedPath}/raw?ref={branch}
```

#### Step 6: 解析测试用例信息
**解析逻辑**:
1. 解析文件全文，提取所有函数和注解
2. 结合diff信息，确定变更影响的函数
3. 提取函数名称和@TestId注解值

**目标输出结构**:
```javascript
[
  {
    "operation": "add|update|delete", // 操作类型
    "name": "fail_CHAIN_TEMPCODEOne_pdf_APPROVE_STATUS_0", // 函数名作为用例名称
    "automationCaseId": "ess-Code6001Test-fail_CHAIN_TEMPCODEOne_pdf_APPROVE_STATUS_0", // @TestId值
    "automationModule": "src/test/java/com/cfca/test/ESS_V4/testcase/", // 代码目录
    "module": "全部用例库/用户认证", // 测试管理目录路径
    "testingFramework": "JUnit", // 测试框架
    "testingFrameworkVersion": "4.12", // 框架版本（可选）
    "testClassName": "Code6601Test", // 测试类名
    "testMethodName": "fail_CHAIN_TEMPCODEOne_pdf_APPROVE_STATUS_0", // 测试方法名
    "repositoryName": "atmTestCode", // 代码库名称
    "filePath": "src/test/java/com/cfca/test/ESS_V4/testcase/Code6601Test.java", // 文件路径
    "branchName": "master", // 分支名称
    "commitId": "26cbed8c9ac3d01c23b5efe75fbdb5dc616f3e34", // 提交ID
    "lastModifiedBy": "osc-admin", // 最后修改人
    "lastModifiedTime": "2025-09-01T15:31:14.000000+08:00" // 最后修改时间
  }
]
```

#### Step 7: 用例同步到测试管理
- 根据`automationCaseId`查询已有用例
- **新增**: `operation=add` 且用例不存在
- **更新**: `operation=update` 且用例已存在  
- **删除**: `operation=delete`（删除代码中的测试函数）

## 三、关键技术点

### 3.1 Diff解析策略
```javascript
// 解析diff，找到变更的行号范围
function parseDiffLines(diffContent) {
  const changes = [];
  const lines = diffContent.split('\n');
  
  for (let line of lines) {
    if (line.startsWith('@@')) {
      // 解析行号范围: @@ -28,7 +30,8 @@
      const match = line.match(/@@ -(\d+),(\d+) \+(\d+),(\d+) @@/);
      if (match) {
        changes.push({
          oldStart: parseInt(match[1]),
          oldLines: parseInt(match[2]),
          newStart: parseInt(match[3]), 
          newLines: parseInt(match[4])
        });
      }
    }
  }
  return changes;
}
```

### 3.2 函数定位策略
```javascript
// 根据变更行号，在完整文件中定位受影响的测试函数
function findAffectedTestMethods(fileContent, diffChanges) {
  const lines = fileContent.split('\n');
  const methods = [];
  
  // 1. 先找到所有测试方法的位置
  for (let i = 0; i < lines.length; i++) {
    if (lines[i].includes('@Test') || lines[i].includes('public void')) {
      // 向上查找@TestId注解
      let testId = null;
      for (let j = i - 5; j <= i; j++) {
        if (j >= 0 && lines[j].includes('@TestId')) {
          testId = extractTestId(lines[j]);
          break;
        }
      }
      
      // 向下查找方法名
      let methodName = null;
      for (let k = i; k < i + 3; k++) {
        if (k < lines.length && lines[k].includes('public void')) {
          methodName = extractMethodName(lines[k]);
          break;
        }
      }
      
      if (testId && methodName) {
        methods.push({
          testId: testId,
          methodName: methodName,
          lineStart: i,
          lineEnd: findMethodEnd(lines, i) // 需要实现方法结束位置查找
        });
      }
    }
  }
  
  // 2. 判断哪些方法受到diff影响
  const affectedMethods = [];
  for (let method of methods) {
    for (let change of diffChanges) {
      if (isLineRangeOverlap(method.lineStart, method.lineEnd, change.newStart, change.newStart + change.newLines)) {
        affectedMethods.push({
          ...method,
          operation: determineOperation(change, method) // add/update/delete
        });
      }
    }
  }
  
  return affectedMethods;
}
```

### 3.3 配置文件处理
```javascript
// 获取并解析配置文件
async function getAutomationConfig(repositoryId, branch) {
  try {
    const configPath = encodeURIComponent('automation-test-map.json');
    const response = await httpClient.get(
      `/projects/${repositoryId}/repository/files/${configPath}/raw?ref=${branch}`
    );
    return JSON.parse(response.data);
  } catch (error) {
    // 配置文件不存在，返回默认配置或抛出异常

    return {
      testingFramework: "JUnit",
      mappings: {} // 空映射，表示所有文件都处理
    };
  }
}
```

## 六、异常处理与边界情况

### 6.1 异常场景处理

| 异常场景 | 处理策略 |
|---------|---------|
| 配置文件不存在 | 记录警告，跳过处理或使用默认配置 |
| 代码平台接口调用失败 | 重试3次，失败后记录日志 |
| diff解析失败 | 记录错误，跳过该commit处理 |
| 测试用例格式不规范 | 记录警告，跳过该函数 |
| 测试管理用例创建失败 | 记录错误，支持手动补偿 |

### 6.2 边界情况处理

1. **多个commit包含同一文件变更**
   - 按时间顺序处理，后提交的覆盖先提交的

2. **同一函数在不同文件中重复**
   - 根据automationCaseId去重，以最新的为准

3. **函数重命名场景**
   - 通过代码位置和上下文判断是重命名还是新增

4. **分支合并场景**
   - 只处理目标分支(通常是master)的推送事件

## 九、错误处理机制

### 9.1 重试策略
- **代码平台API**: 失败重试3次，间隔5秒
- **测试管理API**: 失败重试2次，间隔10秒
- **整体处理**: 单个commit处理失败不影响其他commit

### 9.2 降级处理
- 代码平台不可用时，记录webhook事件，稍后重试
- 解析失败时，保留原始数据，支持手动处理

### 9.3 监控告警
- Webhook处理失败率 > 10%时告警
- 单次处理时间 > 30秒时告警
- API调用失败次数 > 阈值时告警
